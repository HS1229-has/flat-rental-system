1. The Golden Rule: 90% Common vs 10% Unique

In an enterprise Spring Boot microservice ecosystem, 90% of the technical foundation is identical across all services. This consistency is intentional: it enforces clean separation of concerns, guarantees maintainability, and drastically reduces cognitive overhead.

Layer / Component What is Identical (90% Foundation) Why It Matters in Project Review
Layered Architecture Controller ➔ Service ➔ Repository ➔ Entity Strict separation: Controllers handle HTTP, Services handle rules, Repositories handle database SQL.
Data Transfer (DTOs) Entity is decoupled from Client; Request & Response DTOs used. Protects internal DB schema; prevents over-posting and Mass Assignment vulnerabilities.
Database & JPA Spring Data JPA JpaRepository<T, ID> interface with derived queries. No manual JDBC or boilerplate SQL; Dynamic Proxy handles persistence at runtime.
Error Handling @RestControllerAdvice + ApiError DTO + Custom Exceptions. Guarantees uniform JSON errors across all 4 services; no 500 stack trace leaks.
Production Tuning HikariCP Connection Pool (Max: 20, Min-Idle: 5) + Flyway Migrations. Enterprise connection starvation defense and version-controlled SQL schema evolutions.
Testing Framework JUnit 5 + Mockito (@ExtendWith, @Mock, @InjectMocks). Fast, isolated unit tests running in memory without touching physical external databases.

Infrastructure patterns like centralized exception handling, HikariCP connection pooling, and Flyway database migrations are standardized across the entire fleet. The distinction between services lies exclusively in their specific domain business logic."

2. Auth Service: Stateless JWT & Cryptographic Security

Core Mission: Identity issuance, BCrypt password hashing, and stateless token verification.
Key Files: JwtUtil.java, JwtAuthenticationFilter.java, SecurityConfig.java, User.java.

A. BCrypt Password Hashing vs Plain Text

Passwords are never stored in raw text. In SecurityConfig.java, a BCryptPasswordEncoder bean is registered: 

@Bean
public PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder(); // 60-character salted cryptographic hash
}

How it works: BCrypt generates a random 16-byte salt for every password and calculates an adaptive key derivation hash. Even if two users choose the password "password123", their database hashes will be completely different, defeating Rainbow Table brute-force attacks.

B. JWT Token Generation Engine (`JwtUtil.java`)

Uses modern io.jsonwebtoken (jjwt 0.12.x). When a user successfully authenticates, generateToken() packs three claims and signs them with a 256-bit secret key: 

public String generateToken(String username, String role, Long userId) {
    Map<String, Object> claims = new HashMap<>();
    claims.put("role", role);
    claims.put("userId", userId);
    return Jwts.builder()
            .claims(claims)
            .subject(username)
            .issuedAt(new Date())
            .expiration(new Date(System.currentTimeMillis() + 86400000)) // 24 Hours
            .signWith(getSigningKey()) // HMAC-SHA256
            .compact();
}

C. Stateless Request Interceptor (`JwtAuthenticationFilter.java`)

Inherits from OncePerRequestFilter. Intercepts incoming HTTP requests, strips "Bearer " prefix, cryptographically checks the signature and expiry, and populates Spring's SecurityContextHolder: 

UsernamePasswordAuthenticationToken authToken = new UsernamePasswordAuthenticationToken(
        username, null, List.of(new SimpleGrantedAuthority(role)));
SecurityContextHolder.getContext().setAuthentication(authToken);
💡 Viva Question: "Why did you disable CSRF in SecurityConfig?"
"Sir, Cross-Site Request Forgery (CSRF) exploits ambient browser credentials like session cookies. Because our microservices architecture is completely stateless and uses cryptographic JWT tokens transmitted via HTTP Authorization headers (stored in localStorage / client memory), CSRF attacks are fundamentally inapplicable. Disabling CSRF is standard industry best practice for stateless REST APIs."

A. AI-Powered Rent Estimation Algorithm (`estimateRent()`)

Rather than allowing arbitrary or unvalidated pricing, the platform incorporates an intelligent regression pricing heuristic in PropertyService.java exposed via POST /api/properties/estimate-rent.

B. In-Memory Spring Caching (`@Cacheable` & `@CacheEvict`)

Real-estate marketplaces are read-heavy (95% searches, 5% listing creations). Hitting MySQL for every page reload creates severe database bottlenecks.

  • `@EnableCaching`: Activated on PropertyServiceApplication.java.
  • `@Cacheable(value = "properties", key = "'all'")`: First request executes SELECT * FROM properties and stores result in RAM. Subsequent calls return in < 2 milliseconds.
  • `@CacheEvict(value = {"properties", "property"}, allEntries = true)`: Annotated on createProperty(), updateProperty(), and deleteProperty(). Any modification instantly purges stale cache entries.

C. Media Storage Strategy Pattern (AWS S3 vs Local Fallback)

Located in com.flatrental.property.storage. Uses the GoF Strategy Pattern:

  • `MediaStorageService.java` (Interface): Declares contract: uploadImage(...) and deleteImage(...).
  • `AwsS3StorageService.java`: Cloud-native implementation using AWS S3 SDK and CloudFront CDN URLs.
  • `LocalStorageService.java`: Annotated with @Primary @Service. Stores files under /uploads/properties. Crucial for Viva: Guarantees the application runs 100% offline without requiring paid AWS cloud credentials.
💡 Viva Question: "How does your Rent Estimator and Caching work together?"
"Sir, the Rent Estimator uses a multi-factor regression formula evaluating square footage, city base indices, furnishing tiers, and amenities. For listing queries, we use Spring Cache to store search results in-memory. When new listings are added, @CacheEvict flushes the cache to guarantee real-time data consistency without stale reads."

4. Booking Service: Lifecycle State Machine & Tenant KYC

Core Mission: Lease lifecycle management, reservation conflict detection, and government identity verification.
Key Files: BookingService.java, BookingController.java, TenantKycRequest.java, TenantKycResponse.java.

A. Booking Date Conflict Detection & State Machine

Prevents double-booking disasters. Before saving any reservation in BookingService.java:

  • Validates that endDate is strictly chronologically after startDate.
  • Executes date overlap check: Any existing active booking where (requestStart <= existingEnd) AND (requestEnd >= existingStart) triggers a 400 Bad Request.
  • State Transitions: Follows strict finite state flow:
    PENDING ➔ CONFIRMED (Owner Approves) ➔ COMPLETED (Lease Concluded) | CANCELLED

B. Automated Government KYC & CIBIL Verification Engine

6. API Gateway & Interactive Frontend Upgrades

A. Spring Cloud API Gateway (Port 8080)

Configured in api-gateway/src/main/resources/application.yml. Acts as the Reverse Proxy & Single Point of Entry: 

spring:
  cloud:
    gateway:
      routes:
        - id: auth-service
          uri: http://localhost:8081
          predicates:
            - Path=/api/auth/**
        - id: property-service
          uri: http://localhost:8082
          predicates:
            - Path=/api/properties/**
        - id: booking-service
          uri: http://localhost:8083
          predicates:
            - Path=/api/bookings/**

          uri: http://localhost:8084

            - Path=/api/payments/**

CORS Policy: Configured centrally at the Gateway to allow requests from http://localhost:5173 (React Vite Frontend) with methods GET, POST, PUT, DELETE, OPTIONS and headers Authorization, Content-Type.

B. Interactive Map Search (`Properties.jsx` + `leafletMap.js`)

Replaces static grid listings with an interactive real-estate exploration map using Leaflet + OpenStreetMap:

  • Dynamic Loading: leafletMap.js dynamically injects Leaflet CSS/JS at runtime to keep bundle size lightweight.
  • Custom HTML Price Badges: Instead of generic map pins, properties are rendered with glowing gradient price badges (e.g. ₹25,000) using L.divIcon.
  • Click-to-Inspect Popups: Clicking a marker opens a popup card featuring property photo, BHK layout, locality, rent, and a direct link to property details.
  • City Auto-Pan: Selecting Mumbai, Bangalore, Delhi, Pune, etc. smoothly flies the map view to that city's geographic coordinates.
  • Zero Cost: Uses open-source OpenStreetMap tile servers with zero third-party billing or API keys required.

C. Automatic JWT Interceptor (`axiosConfig.js`)

In React frontend, an Axios request interceptor attaches the token to every outgoing request: 

api.interceptors.request.use((config) => {
  const token = localStorage.getItem('token');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

7. Top 10 Viva Rapid-Fire Questions & Model Answers

# Examiner Question Your 20-Second Model Answer
1 Why Microservices instead of a Monolith? "Microservices provide independent deployability, fault isolation, and targeted scaling. If payment service experiences high load, it can scale independently without bottlenecking property search."
2 What is the purpose of the API Gateway? "The API Gateway is our reverse proxy on port 8080. It shields internal services, routes requests based on URL paths, and handles centralized CORS and authentication filters."
3 Why use JWT instead of standard HTTP Sessions? "JWT is completely stateless. The server doesn't store session states in RAM, allowing services to scale horizontally behind a load balancer without sticky session dependencies."
4 Why BCrypt instead of SHA-256 or MD5? "MD5 and SHA-256 are fast general hash functions vulnerable to GPU-based Rainbow Table attacks. BCrypt includes a built-in 16-byte random salt and a configurable work factor to resist brute force."
5 How does Spring Data JPA work without SQL? "We declare interfaces extending JpaRepository. At runtime, Spring uses Java Dynamic Proxies to parse method names like findByUsername and automatically generate optimized SQL queries."
6 Why use DTOs instead of passing Entities to Frontend? "DTOs prevent Mass Assignment vulnerabilities, avoid leaking sensitive internal fields (like hashed passwords), eliminate Hibernate lazy-loading circular references, and decouple frontend contracts from DB schema."
7 How do you prevent double-booking? "In BookingService, we execute an overlap validation query before saving. If any active booking exists where the requested dates intersect (start <= existingEnd AND end >= existingStart), it throws an exception."
8 How does your AI Rent Estimator calculate rent? "It uses a heuristic pricing model: base rate per sqft by city, multiplied by bedroom layout weights, with a 22% premium for full furnishing and discrete monetary bonuses for gym, parking, and security."
9 What is HikariCP and why is it tuned? "HikariCP is the high-performance JDBC connection pool. We tuned maximum-pool-size to 20 and minimum-idle to 5 to prevent connection starvation under concurrent user load."
10 What is Mockito and why use it for Unit Testing? "Mockito mocks external dependencies like JPA repositories with @Mock and injects them into @InjectMocks services. This allows testing business logic in complete isolation without hitting a real database."
