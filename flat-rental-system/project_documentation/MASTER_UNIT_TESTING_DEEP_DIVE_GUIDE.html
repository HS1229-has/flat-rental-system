1. The Fundamentals of Unit Testing & Mockito Mechanics

Unit testing verifies that a small, isolated piece of code (a single method or class) performs exactly as intended under both valid and erroneous inputs. In enterprise Spring Boot development, unit tests do not start an actual web server (Tomcat) and do not connect to a physical MySQL database.

Concept / Annotation What it Does in Code Why We Use It (Enterprise Benefit)
@ExtendWith(MockitoExtension.class) Initializes the Mockito testing framework on JUnit 5 test classes. Enables automatic initialization of mocks without writing boilerplate openMocks() setup code.
@Mock Creates a fake dummy instance of a dependency (e.g., UserRepository). Isolates the class under test. No real database queries or network sockets are ever touched.
@InjectMocks Creates the real instance of the service and injects all @Mock fields into it. Emulates Spring's Dependency Injection (DI) mechanism inside memory in a fraction of a millisecond.
when(...).thenReturn(...) Stubbing: Instructs a mock object to return a predefined value when called. Simulates any scenario (e.g., user exists, property found, credit score high) on demand.
assertThrows(...) Verifies that executing a lambda throws the exact expected exception. Essential for negative testing (verifying that invalid inputs trigger proper 400/404/409 errors).
verify(mock, times(1)) Checks whether a mock method was invoked the expected number of times. Proves that side-effects happened (e.g., save() called once) or didn't (never() called on errors).
MockMvc Spring's virtual HTTP client that executes controller endpoints in-memory. Tests HTTP routing, JSON serialization, and GlobalExceptionHandler without starting a real port.
💡 The AAA (Arrange-Act-Assert) Pattern:
Every test method in our project follows this clean structure: 1. Arrange (Given): Prepare mock inputs and stub mock behaviors with when().thenReturn().
2. Act (When): Invoke the actual service method (e.g., authService.register(request)).
3. Assert (Then): Check returned values with assertEquals / assertNotNull, and verify interactions with verify().

// 1. SUCCESSFUL REGISTRATION TEST
@Test
void testRegister_Success() {
    RegisterRequest request = new RegisterRequest();
    request.setUsername("newuser");
    request.setEmail("new@example.com");
    request.setPassword("password123");
    request.setFullName("New User");
    request.setPhoneNumber("9999999999");
    request.setRole("TENANT");

    // Stubbing repository checks
    when(userRepository.existsByUsername("newuser")).thenReturn(false);
    when(userRepository.existsByEmail("new@example.com")).thenReturn(false);
    when(passwordEncoder.encode("password123")).thenReturn("hashed123");
    when(userRepository.save(any(User.class))).thenAnswer(inv -> {
        User u = inv.getArgument(0);
        u.setId(10L);
        return u;
    });

    UserResponse response = authService.register(request);

    assertNotNull(response);
    assertEquals(10L, response.getId());
    assertEquals("newuser", response.getUsername());
    assertEquals("ROLE_TENANT", response.getRole());
    verify(userRepository, times(1)).save(any(User.class)); // Database save verified!
}

// 2. DUPLICATE USERNAME NEGATIVE TEST
@Test
void testRegister_DuplicateUsername() {

    when(userRepository.existsByUsername("testuser")).thenReturn(true);

2 What is Mockito Stubbing? "Stubbing is programming a mock object's behavior using when().thenReturn(). It tells the mock: 'When method X is called with argument Y, return fake answer Z without executing real database queries.'"
3 Why do you verify() with never() in negative tests? "In negative exception tests, verifying never().save() proves data integrity: if an error or duplicate user occurs, the system halted execution immediately and never attempted to write corrupted data to MySQL."
4 How does MockMvc test controllers without Tomcat? "MockMvc uses Spring's MockServletContext to build a mock HTTP environment. It serializes JSON payloads, invokes controller mapping annotations, and verifies HTTP status codes and JSON responses in memory."
5 Why use ParameterizedTest in JUnit 5? "@ParameterizedTest with @ValueSource allows executing the same test logic across multiple input variations (like 10 different invalid phone numbers or email strings) without duplicating code."
